# ADR 0050 — The incremental collector

## Context

Phase 3.27's stop-the-world collector decides Lua's weak-table, ephemeron, and finalizer semantics correctly, but every collection pauses for the whole heap, its work is not charged to fuel, and `collectgarbage("incremental")`, `setpause`, `setstepmul`, and a real `step` were missing. Moonseed must also checkpoint at any point, and give the same result whatever quantum the executor runs with. Lua 5.4 does incremental collection with a tri-color invariant, a backward barrier on tables, threads re-traversed in its atomic phase, and two whites so its sweep can tell new objects from dead ones.

## Decision

**A state machine that is snapshot state.** `gc::Collector` holds the phase (Pause, Begin, Propagate, Atomic, Sweep), the gray stack, the object being scanned and its position, the weak tables reached, the ephemeron tables waiting, the values waiting on their keys, the atomic step and its cursors, and the sweep's count. `gc::work` does units of work from it; nothing about a cycle lives in Rust locals between units.

**Marks.** One byte per arena slot, in a dense array beside the slots: two whites, gray, black, free. At the end of the atomic phase the whites swap, so an object left with the old white is dead and one made since has the new white. Each arena counts its marked and its dead objects; dead objects waiting for the sweep are not live objects (`Arena::live`, `Arena::iter`, so `find_by_id`), are never handed out, and are not written to snapshots.

**New objects.** While a cycle marks, a new string is black and any other new object gray, on its arena's `again` list, traced in the atomic phase: an object made during a cycle survives it. Otherwise a new object has the current white, which during the sweep is the new white, so the sweep never frees it.

**One barrier authority.** `Arena::get_mut` is the only mutable access to a heap object outside the collector, which alone uses `Arena::raw_mut`. While a cycle marks, `get_mut` turns a black object about to change gray and puts it on `again` (Lua's backward barrier), for every kind: tables (entries, keys, metatables), userdata (metatable, user values), upvalues, closures (`upvaluejoin`), native closures, threads (stack, frames, results), and prototypes. No write site calls a barrier, so none can forget one. The roots the heap holds as fields (globals, registry, type metatables, host roots, the active and entry threads, the runtime's pins, the finalizer queue, the closing closure) are not barriered: the atomic phase grays every root again. A host root asked for during the atomic phase (`Runtime::root_id`) first finishes it, so it never names an object the cycle has already found dead. Phase 3.29's old-to-young check belongs in the same place.

**Bounded work.** A unit is an object begun, a reference traced (a table slot, a stack slot, a frame, a constant), a weak table's entry checked or cleared, a weak mode read, or an object swept. Tables, thread stacks, and prototypes are traced from a stored position, so a 10,000-entry table is traced in pieces. Some batches run whole once begun, each bounded by the object limit or a small constant: an object's few references (a closure's upvalues, at most 16 native-closure values, a userdata's user values), a thread's open upvalues (one position: a restore rebuilds their list in another order), the values waiting on a key, the roots, and moving the dead registered objects to the queue.

**Determinism.** A step owes units (`GcState::owed`) and does that many, finishing a batch it began. An atomic phase, once begun, runs to its end before Lua runs again, whatever the step owed; a full collection does the same. Every decision depends on the units done, never on how many a slice was allowed: the quantum decides where the executor pauses, not what the collector does. Entries of a weak-key table are marked one by one, so whether a value waits on its key never depends on where a slice ended. The collector's events (phase changes with the work done at each, cycle ends) fold into `GcState::trace`, snapshot state; tests compare it across quanta and checkpoints.

**Work is fuel.** A unit of fuel pays for `WORK_PER_FUEL` (4) units of work, in advance; what it paid for and was not used carries over (`GcState::prepaid`), so how the work is split never changes its cost. Emergency collections are charged too; the host's `Runtime::collect` is the host's own work and is not. The executor stops a slice when its quantum is spent and resumes the same work. Fuel revision 6.

**Scheduling** (`GcState::sched` is Lua's `GCdebt`). A cycle begins once the allocation since the last one reaches the threshold: `pause` percent of what the last cycle kept, less what it kept (Lua's `setpause`); at least `min_debt` while the pause is above 100, so a pause of 100 or less cycles at once; at most half the room under the object limit and under the quota. During a cycle a step comes every 2^`stepsize` logical bytes and owes `stepmul` units per KiB allocated, the multiplier's documented meaning ("how many elements it marks or sweeps for each kilobyte of memory allocated"). Lua's own `incstep` does 64 times that per byte, so its default step finishes a small heap's whole cycle; Moonseed keeps steps small. A step also owes at least its share of finishing a cycle as long as the last one within half the room left under the limits, so a heap near them is collected in time. What a cycle kept is what it traced, as it was then, and what was made while it marked; allocation during its sweep counts toward the next cycle. A finalizer's end still gives the interrupted code `min_debt` before the next step (ADR 0048). Logical bytes, never allocator bytes.

**The atomic phase**, in Lua's `atomic` order, each step resumable: gray the roots again; trace (the `again` lists first, then the gray stack, ephemerons last, values released as their keys are marked); read the mode of every weak table seen again, and trace again, with its present mode, any whose mode changed, so a table made strong late keeps what it holds; trace that; clear weak values; move the registered objects left white to the queue, newest registration first, and trace them (resurrection); clear weak keys, and the weak values of tables first reached by resurrection; trace anything grayed since (only a host can), and swap the whites. Phase 3.27's semantics are unchanged but for one detail, changed in its reference collector too: in a table weak both ways, a string key whose value is a collectable object waits on that value, so it goes with its entry, as in Lua.

**Full and emergency collections.** `gc::request_full` abandons a cycle still marking (its marks are made white again by a sweep that frees nothing, Lua's `entersweep`), lets one past its atomic phase finish, then runs one whole cycle: finalizers are queued as one collection would queue them. `collectgarbage("collect")` asks for one and does its work in charged units before it returns; an emergency collection (an allocation that needs room) and `Runtime::collect` do it at once. An allocation still refused after one emergency collection raises a memory error; finalizers never run inside one.

**`collectgarbage`.** `incremental [pause [stepmul [stepsize]]]` returns `"incremental"` and leaves a 0 alone; `setpause` and `setstepmul` return the previous value and store the new one as `lua_gc` does (divided by four in a byte, so `setpause(150)` reads back 148 and 1024 wraps to 0); `step(0)` does one basic step; `step(n)` adds n KiB to the debt and steps only if a step is then due (a negative or small n may not); both work while stopped and return true when the step ends a cycle, after the finalizers it queued have run. `stop` stops scheduled steps; `restart` makes one due at the next allocation, as Lua's sets the debt to 0. Inside a finalizer every option returns nil, as before. `generational` stays an error until Phase 3.29.

**Snapshots** (schema 17). A collector section: the parameters and schedule, the phase and atomic step, the current white, every object's mark but the current white, the gray stack, the `again` lists, the scan and its position, the weak and ephemeron lists, the waiting values by key, the cursors, the cycle's byte and work bases, and the sweep's count. A snapshot never finishes or resets a cycle. Restore refuses an unknown phase or step, a third white, marks other than gray and black, an object marked or listed twice, lists in phases that have none, a gray-listed object not gray, a scan of the wrong kind or past its object (unless written to since), cursors outside their lists or tables, a sweep count below the objects it must still pass, prepaid work of a unit or more, a finalizer running during an atomic phase, values waiting on a string, a gray object in no list while marking, a full collection asked for more than two cycles ahead, and a marking state in which a black object refers to a white one (the tri-color invariant, checked once the heap is rebuilt). The physical sweep position is not snapshot state: restored, the sweep starts over its slots and passes only the objects it has not.

## Alternatives

- **White new objects** (Lua's choice): measured no faster on allocation-heavy rows here; a gray new object is simpler to reason about across every phase.
- **Barrier calls at each write site, forward or backward:** dozens of sites in the interpreter, natives, and debug functions to audit now and again in Phase 3.29. Turning the mutable accessor into the barrier covers them all.
- **Lua's step arithmetic** (`bytes / 16 * stepmul`): every default step would be a whole cycle on the heaps Moonseed's limits allow, so pauses would be no shorter than stop-the-world.
- **Finishing a cycle before a snapshot:** a checkpoint would change when objects die and finalizers run.
- **Writing dead objects as stubs:** restore would rebuild objects nothing can reach; counting the sweep's remaining work is enough.

## Consequences

Snapshot schema 17, fuel revision 6, GC policy 10; bytecode 11, tables 3, binary chunk format 2 unchanged. The Phase 3.27 collector stays as `gc_reference.rs`, built for tests and measurements only. A completed cycle decides exactly as it does on thousands of random heaps; with changes made between slices, it frees nothing the final heap reaches and settles where the reference does.

**From the milestone review** (one round, by a separate reviewer; no blockers):
- Major, fixed: `Runtime::call_closure` and `Runtime::resume_thread` by id while the run was paused in an atomic phase: the resumed thread became the active thread after the roots were grayed and was freed, and a closure first traced in the last step left a weak table it reached uncleared, so a real checkpoint failed to restore. Every host call that names objects by id, roots one, completes a wait, or runs Lua now finishes an atomic phase first.
- Major, fixed: restore accepted gray objects in no list, a full-collection target no run sets (the collector cycled for ever), and a schedule whose arithmetic overflowed. Restore now requires every gray object to be listed while marking, a target at most two cycles ahead, and checks the tri-color invariant of a marking state; the schedule's arithmetic saturates.
- Minor, fixed: the estimate of what a cycle kept counted an object traced again, or made while marking, twice (up to 1.74× the heap), so the quota refused early and forced emergency collections. An object grayed again is uncounted before it is traced again.
- Minor, accepted: a value waiting on an ephemeron key is not withdrawn when its entry is overwritten or the table's mode changes; marking the key later keeps it one cycle longer. Never freed early.
- Minor, accepted: skipping free and white slots in the sweep, the reset sweep's drain, and the end of a cycle's pass over the slots are not charged; each is bounded by the slots, at most twice the object limit per arena.
- Held up: ten torture programs (coroutines, the debug library, resurrection, mode changes, errors and to-be-closed values, `gsub` callbacks, deep recursion, ephemeron chains) gave the same output, fuel, events, and work straight, at quantum 1 with the invariant checked at every step, and restored every 5 to 13 steps; nine match Lua 5.4.9 exactly and the tenth differs only in finalizer counts that depend on when cycles end; a full collection from any phase matched Lua over 60 trials; `collectgarbage`'s encodings and the both-weak-table change matched Lua.
